    <!-- MAIN CONTENT -->
    <main class="main-content">
        <div class="container">

            <!-- Intro Note -->
            <div class="info-box">
                <p><strong>Important:</strong> The "Reassign Case" function only works between teams that are already using DX Salesforce. For teams outside of DX Salesforce, traditional methods like email must still be used.</p>
            </div>

            <!-- SECTION 1: TRANSFER -->
            <h2>Transfer a Case</h2>
            <p><strong>Purpose:</strong> A transfer is used to move a case that was assigned to the wrong queue. Common reasons include being sent to the wrong regional queue, wrong product queue, or if a "Product" case is actually a "General" case.</p>
            
            <!-- Standard Vertical Block (Removed Grid) -->
            <div class="content-block">
                <ul>
                    <li>Navigate to the <strong>Reassign Case</strong> tab within the case record.</li>
                    <li>Select the option <strong>Transfer to Frontline Queues</strong>.</li>
                    <li>Choose the correct queue to send the case to from the provided list.</li>
                    <li>Depending on the queue, you may need to select the Case Product or review an AI-generated summary.</li>
                    <li>Click <strong>Finish</strong> to complete the transfer.</li>
                </ul>

                <!-- IMAGE MOVED TO BOTTOM OF SECTION (Vertically Stacked) -->
                <div class="img-wrapper">
                    <img src="https://sgmyserviceguide.trimblesea.com/InternalGuide/transfercase.png" alt="Transfer Case Interface showing Frontline Queues selection" class="content-img" onerror="this.onerror=null; this.src='https://placehold.co/800x500?text=Transfer+Case+Image+Not+Found';">
                    <p class="img-caption">Select "Transfer to Frontline Queues"</p>
                </div>
            </div>

            <!-- SECTION 2: ESCALATE -->
            <h2>Escalate a Case</h2>
            <p><strong>Purpose:</strong> An escalation is used to move a case from a frontline (Tier 1) agent to a more skilled Tier 2 support team when higher-level expertise is required to resolve a complex issue.</p>
            
            <h3>How to Escalate a Case to Tier 2</h3>
            <ul>
                <li>Navigate to the <strong>Reassign Case</strong> tab within the case record.</li>
                <li>Select the option <strong>Escalate to Tier 2 Queues</strong>.</li>
                <li>From the list, choose the correct Tier 2 team (e.g., Americas Product Support, EMEA Product Support).</li>
                <li><strong>Important:</strong> The <strong>Case Product</strong> field must be correctly filled out on the case before you can escalate. If it's missing, you must add it via the "Case Coding" tab first. For Trimble Connect, an Escalation Reason is required.</li>
                <li>It is best practice to add a detailed post on the case feed explaining the steps already taken before escalating.</li>
                <li>Click <strong>Next/Finish</strong> to complete the escalation.</li>
            </ul>

            <h3>What Happens After Escalation</h3>
            <ul>
                <li>The Case Owner will be changed to the selected Tier 2 team queue.</li>
                <li>The case <strong>Status</strong> will be set to "New".</li>
                <li>The case <strong>Sub-Status</strong> will be set to "Escalated".</li>
                <li>The case <strong>Tier</strong> will be updated to "Tier 2".</li>
            </ul>

            <div class="info-box">
                <p><strong>De-Escalation:</strong> A Tier 2 agent can de-escalate a case back to Tier 1 if necessary. This reassigns the case to its previous owner and sets the Tier back to "Tier 1".</p>
            </div>
